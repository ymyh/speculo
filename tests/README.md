# Tests

Test sources are grouped by the public API they exercise, not by the development
phase that introduced them. Add a test to the file that matches its feature; a new
feature normally gets a new `*_test.cpp` file.

The general method (contract → partitions → combinations → assertions → coverage
ledger) is the `contract-tests` skill. The speculo-specific supplement — layers,
value classes, matrix budget, error precedence, naming, run commands, acceptance —
is in @.agents/testing.md. This file only lists what exists.

Files that carry a **value-class matrix** keep the expected-result table in a
comment above the loop, and every cell of the product is asserted:

are generated by `tools/gen_matrix.py` (prints the C++ initializer; rerun it after
changing an error-precedence rule). The other matrices derive their expectations
from per-row data, so their tables are written literally next to the loop.

## Shared fixtures

Fixture types live in `tests/support/` and are included after the module imports,
because their inline members use `std`, `crab_cpp` and `speculo`:

```cpp
#include <gtest/gtest.h>

import std;
import crab_cpp;
import speculo;

#include "support/class_fixtures.h"
```

Each header keeps its types in an unnamed namespace, so every translation unit
gets its own copy (the same ownership the tests had when they shared one file).
Two headers are exceptions, because their tests need canonical names:
`registry_fixtures.h` (its types live in the namespaces the registry tests look up:
`p6`, `p6b`, `p6c`, `p6ann`) and `type_graph_fixtures.h` (namespace `tg`, so the
relation tests can assert by name and keep one type — `tg::Unregistered` — that is
never passed to `class_of<T>()`).
