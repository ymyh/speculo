# Tests

Test sources are grouped by the public API they exercise, not by the development
phase that introduced them. Add a test to the file that matches its feature; a new
feature normally gets a new `*_test.cpp` file.

How to write, run and judge tests (layers, per-API coverage matrix, assertion
discipline, v2 techniques) is documented in @.agents/testing.md — this file only
lists what exists.

Files that carry a **value-class matrix** keep the expected-result table in a
comment above the loop, and every cell of the product is asserted:

| Test suite | File | Product |
| --- | --- | --- |
| `MethodInvokeMatrix` | `method_test.cpp` | receiver form × argument form (5 × 5) |
| `FieldSetMatrix` | `field_test.cpp` | receiver form × value form (5 × 5) |
| `ClassMethodLookupMatrix` | `class_test.cpp` | lookup way × target (5 × 4) |
| `ConstructorNewInstanceMatrix` | `constructor_test.cpp` | constructor set × argument form (5 × 5) |
| `ArrayOperationMatrix` | `array_test.cpp` | object form × operation (5 × 4 + the `Option` column) |
| `CastMatrix` | `inheritance_test.cpp` | target base × receiver constness (5 × 2) |
| `EnumConversionMatrix` | `enumerator_test.cpp` | enum × conversion (4 × 6) |
| `IntBindingMatrix`, `NumericExactMatchMatrix`, `PointerBindingMatrix`, `BoxBindingMatrix`, `OptionStateMatrix`, `ResultStateMatrix` | `function_test.cpp` | free-function arguments / return kinds |

The precedence tables (`MethodInvokeMatrix`, `FieldSetMatrix`, `ClassMethodLookupMatrix`)
are generated by `tools/gen_matrix.py` (prints the C++ initializer; rerun it after
changing an error-precedence rule). The other matrices derive their expectations
from per-row data, so their tables are written literally next to the loop.

## Shared fixtures

Fixture types live in `tests/support/` and are included after the module imports,
because their inline members use `std`, `crab_cpp` and `speculo`:

```cpp
#include <gtest/gtest.h>

import std;
import crab_cpp;
import speculo;

#include "support/class_fixtures.h"
```

Each header keeps its types in an unnamed namespace, so every translation unit
gets its own copy (the same ownership the tests had when they shared one file).
`registry_fixtures.h` is the exception: its types live in the named namespaces
the registry tests look up (`p6`, `p6b`, `p6c`, `p6ann`).
